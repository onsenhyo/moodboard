# 무드보드 앱 설계 (kaleidoscope)

작성일 2026-11-14 · 상태: 사용자 승인 대기 · 빌더 검토 반영

## 1. 무엇을, 왜

유튜브 영상, 핀터레스트 핀, 이미지, MP4, 짧은 글을 한 보드에 썸네일 카드로 모아 두는 개인 무드보드입니다. 주인 한 사람이 PC에서 채우고 정리합니다. 다른 사람에게는 **읽기 전용**으로 보여 줍니다.

kaleidoscope 앱으로 만들고, 공유할 때만 정적 웹페이지 하나로 내보냅니다(사용자 결정).

## 2. 목표 / 비목표 / 반목표

**목표**
- Finder에서 끌어다 놓기, 입력칸에 링크나 글 붙여넣기로 자료를 넣는다.
- 자유 캔버스에 카드를 손으로 배치한다(겹치기, 이동, 크기 조절).
- [색으로 정렬] 버튼을 누르면 카드가 대표 색 순서로 정리되고, [내 배치]를 누르면 손으로 놓은 자리로 돌아온다(목업 C, 사용자 선택).
- 보드를 HTML 파일 하나로 내보낸다. 그 파일만 있으면 오프라인에서도 보이고, 정렬 전환도 그대로 된다.

**비목표(이번 판)**
- 폰에서 넣기, 모바일 화면(사용자 결정: PC 전용).
- 여러 사람이 같이 편집하기, 서버에 호스팅해 실시간으로 공유하기.
- 아무 웹사이트에서 og:image를 긁어 오기.

**반목표(이렇게 되면 실패)**
- 넣는 동작이 번거로워 결국 안 쓰게 되는 것. 끌어다 놓기와 입력칸 붙여넣기는 각각 한 번의 동작으로 끝나야 한다.
- 정렬 버튼을 누른 뒤 손으로 놓은 배치가 사라지는 것.
- 내보낸 파일이 너무 커서 공유가 불편한 것. 그래서 MP4는 기본적으로 정지 장면만 넣는다.

## 3. 검토한 방식

| 방식 | 장점 | 단점 | 결과 |
|---|---|---|---|
| 웹 앱을 인터넷에 올리기 | 폰 넣기와 링크 공유가 자연스럽다 | 서버와 로그인을 직접 관리해야 한다 | 채택 안 함 |
| **kaleidoscope 앱 + HTML로 내보내기** | 지금 쓰는 쉘 안에서 정리할 수 있고 서버가 필요 없다 | 폰 넣기가 약하고, 공유할 때마다 내보내기가 필요하다 | **사용자 선택** |
| 기존 서비스(Cosmos, Are.na, Eagle) | 만들 필요가 없다 | 종류가 다른 자료를 한데 섞어 색 정렬해 주는 서비스가 없다 | 채택 안 함 |

화면 배치는 무지개 벽돌 벽(A), 색 덩어리 섬(B), 자유 캔버스 + 정렬 버튼(C)을 비교했고, 사용자가 **C**를 골랐습니다.

## 4. 플랫폼 제약 (kaleidoscope 소스로 확인함)

- 화면은 `client`와 `canvas`로 그립니다. canvas 블록은 `on_pointer`만 받고 키보드, 휠, 붙여넣기, 드롭 이벤트는 받지 않습니다. 그래서 확대와 축소는 화면 버튼으로 합니다.
- 파일 넣기는 앱 수준 `file_drop`(`requires.blocks` ≥45, `client` ≥7)으로 받습니다. 끌어다 놓은 좌표는 앱에 오지 않습니다. 파일 하나는 512MiB까지입니다. `pick_files` 버튼도 함께 둡니다.
- ⌘V로 붙여넣기는 불가능합니다. 웹페이지의 이미지나 URL을 끌어오는 것도 불가능합니다. 대신 `input` 블록에 붙여 넣으면 state를 거쳐 client가 읽습니다.
- **여러 PC에서 씁니다(사용자 답변).** 이를 위해 사용자가 원격 서버(별도 orchestrator)를 띄우고 각 PC의 쉘을 연결합니다. 앱 `storage`는 서버를 통해 계정 단위로 동기화되지만, client `blobs`는 기기별이라 동기화되지 않습니다.
- 그래서 저장은 이렇게 나눕니다.
  - **보드 메타데이터**(카드 목록, 위치, 색, 텍스트, 링크): 보드마다 `storage` 문서 하나. 동기화됩니다.
  - **썸네일**: client가 모음 문서를 쓸 수 없어서(Task 1 확인) 고정 항목 `thumbs_000`~`thumbs_127`에 나눠 담습니다. 카드당 base64 약 100KB(긴 변 640px)이며, 전체 약 1,200장이 한도입니다(사용자 승인). 동기화됩니다.
  - **원본 이미지와 MP4**: 넣은 PC의 `blobs`(`device_storage.prefixes`)에만 둡니다.
- 원본이 없는 PC에서 동작하는 방식은 다음과 같습니다. 이미지 크게 보기에는 썸네일을 씁니다. MP4는 정지 장면과 "원본은 다른 PC에 있음" 안내를 보여 줍니다. "재생 포함" 내보내기는 원본이 있는 PC에서만 켤 수 있습니다.
- client가 모음 문서를 읽고 쓸 수 있는지(`storage_entries`)는 빌더가 먼저 확인합니다. 안 되면 계획을 세우기 전에 알려 주어야 합니다.
- 외부 자료는 `http.read`로 가져오며, 선언한 호스트와 경로만 허용됩니다. 와일드카드와 리다이렉트는 쓸 수 없습니다. 선언할 곳은 다음과 같습니다.
  - `https://www.youtube.com/` 의 `/oembed` (제목)
  - `https://i.ytimg.com/` 의 `/vi/` (썸네일)
  - `https://www.pinterest.com/` 의 `/oembed.json` (핀 썸네일 주소)
  - `https://i.pinimg.com/` 의 `/originals/`, `/1200x/`, `/736x/`, `/564x/`, `/474x/`, `/236x/` (핀 이미지)
- 사용자는 핀터레스트 링크를 웹 브라우저 주소창에서 복사합니다(사용자 답변). `kr.pinterest.com`, `pinterest.co.kr` 같은 주소는 핀 ID를 뽑아 `www.pinterest.com/pin/<id>/`로 바꾼 뒤 oEmbed에 넣습니다. `pin.it` 짧은 주소는 리다이렉트라서 지원하지 않고, 카드에 "브라우저 주소창의 주소를 넣어 주세요"라고 안내합니다. worker는 쓰지 않습니다. 그 외 링크는 썸네일 없이 제목(URL)만 있는 카드가 됩니다.
- 내보내기는 `files.save_prompt` → `files.write` 순서로 하며, 매번 OS 저장 창이 뜹니다.
- 바깥 링크는 client가 직접 열 수 없습니다. 선택한 카드의 URL을 state에 두고, 옆 칸의 `open_url` 버튼이나 `web_view`로 엽니다.

## 5. 설계

### 카드 종류
| 종류 | 넣는 법 | 썸네일 | 클릭하면 |
|---|---|---|---|
| 이미지 | 끌어다 놓기 / 파일 선택 | 원본을 축소한 이미지 | 옆 칸에 크게 보기 |
| MP4 | 끌어다 놓기 / 파일 선택 | 영상 1초 지점의 장면 | 옆 칸에서 재생(`media` 블록, blob) |
| 유튜브 | 입력칸에 URL | i.ytimg 썸네일과 oEmbed 제목 | 옆 칸 `web_view`에서 재생하고 [브라우저로 열기]도 둔다 |
| 핀터레스트 | 입력칸에 pinterest.com/pin URL | oEmbed가 주는 이미지 | 옆 칸에 크게 보기와 [브라우저로 열기] |
| 글 | 입력칸에 텍스트(URL이 아닌 입력) | 종이 질감의 텍스트 카드 | 옆 칸에서 전문 보기와 고치기 |
| 기타 링크 | 입력칸에 URL | 도메인과 URL만 보이는 카드 | [브라우저로 열기] |

### 대표 색과 정렬
- 썸네일을 작게 줄여 픽셀을 모은 뒤 가장 많이 나오는 색(채도 가중)을 대표 색으로 정하고, 카드 데이터에 저장합니다.
- 글 카드는 사용자가 고른 색 점을 대표 색으로 씁니다. 기본값은 회색입니다.
- [색으로 정렬]은 색상(hue) 순서로 줄을 맞춰 배치합니다. 채도가 낮은 카드는 끝의 무채색 구역으로 보냅니다. 전환할 때는 카드가 미끄러지듯 움직입니다.
- [내 배치]는 저장해 둔 수동 좌표로 돌아갑니다. 정렬 모드에서는 카드를 옮길 수 없습니다. 옮기려 하면 "내 배치로 전환" 안내를 보여 줍니다.

### 캔버스 조작
- 카드 드래그로 이동, 모서리 드래그로 크기 조절, 빈 곳 드래그로 화면 이동, [+]/[−]/[맞춤] 버튼으로 확대와 축소를 합니다.
- 새 카드는 지금 화면의 가운데에 살짝 흩어 놓습니다.
- 카드를 선택하면 오른쪽 칸에 상세와 동작(열기, 삭제, 글 카드 색 변경, MP4 "내보내기에 재생 포함")이 나옵니다.

### 보드
- 보드는 여러 개를 둘 수 있습니다. 상단 드롭다운으로 고르고, 새로 만들기와 이름 바꾸기를 지원합니다.

### 내보내기
- [내보내기] → OS 저장 창 → `보드이름.html` 파일 하나가 만들어집니다.
- 썸네일은 data URL로 파일 안에 넣습니다(긴 변 약 800px, JPEG).
- MP4는 정지 장면만 넣습니다. 카드에서 "재생 포함"을 켠 영상만 원본을 넣고, 저장 창 전에 예상 파일 크기를 보여 줍니다.
- 크기 기준(설계자 판단): 예상 크기가 50MB를 넘으면 경고합니다. 95MB를 넘으면 내보내기를 막고, 어떤 영상의 "재생 포함"을 끄면 되는지 알려 줍니다. GitHub의 파일당 100MB 제한에 맞춘 기준입니다. 파일은 한 번에 만들지 않고 조각으로 나눠 씁니다(`files.write` offset).
- 내보낸 페이지에서 할 수 있는 것: 화면 이동과 확대·축소, [색으로 정렬]/[내 배치] 전환, 카드를 클릭해 크게 보기, 유튜브·핀터레스트 원본으로 이동. 편집은 없습니다.
- 외부 의존성이 없는 단일 HTML이라 Netlify Drop이나 GitHub Pages에 그대로 올리면 링크로 공유됩니다.

## 6. 빌더에게 맡기는 것
- 대표 색을 뽑는 정확한 알고리즘, 정렬 배치의 격자 크기와 애니메이션.
- 화면 색과 질감 같은 시각 디테일. 단, kaleidoscope 테마와 어울려야 합니다.
- 내보낸 HTML의 내부 구조.
- 앱 정의 필드는 `upload_app` 입력 스키마를 정본으로 따르고, 필요한 `requires` 판을 맞춥니다.

## 7. 확인 방법
- `preview_app`에서 warnings 0, 그다음 `upload_app` 후 `get_workspace`로 data_errors 0을 확인합니다.
- 같이 보기 창에서 다음을 실제로 해 봅니다: 이미지와 MP4 각 1개 끌어다 놓기, 유튜브·핀터레스트 URL과 글 각 1개 넣기, 정렬 전환을 왕복해 수동 좌표가 유지되는지 확인, 내보낸 HTML을 브라우저로 열어 오프라인 표시와 정렬 전환 확인.
- 끌어다 놓기와 OS 저장 창은 에이전트가 조작할 수 없으므로 사용자에게 부탁합니다.
